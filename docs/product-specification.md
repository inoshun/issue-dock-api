# IssueDock プロダクト仕様書

## 1. この文書について

この文書は、チーム向け課題管理ツール「IssueDock」で「誰の、どのような課題を、どの機能によって解決するか」を定義するためのものです。

画面や機能の期待される振る舞い、利用者の権限、初期リリースの範囲を扱います。システム構成、データの保存方法、外部との通信方法、使用する技術などの技術設計は扱いません。

| --- | --- |
| 文書の状態 | 初版 |
| 対象 | 初期リリース（MVP） |
| 最終更新日 | 2026-09-17 |
| プロダクト名 | IssueDock（イシュードック） |

## 2. プロダクトの概要

IssueDockは、小規模なチームが取り組む課題を一か所に集め、担当者や進捗を共有するためのWebアプリケーションです。

利用者はワークスペースに参加し、プロジェクトごとに課題を登録します。各課題には担当者、状態、優先度、期限などを設定でき、関係者はコメントを通じて補足や相談を行えます。

多機能なプロジェクト管理を目指すのではなく、チームが「何をするのか」「誰が担当しているのか」「現在どうなっているのか」を迷わず確認できることを重視します。

## 3. 解決したい課題

小規模なチームでは、やるべきことが口頭、チャット、個人のメモなどに分散しがちです。その結果、次のような問題が起こります。

- 誰が何を担当しているのか分からない
- 課題が未着手なのか、対応中なのか、完了したのか分からない
- 課題に関する経緯や補足が別の場所に散らばる
- 優先すべき課題や期限が近い課題を見落とす
- 関係のない利用者にチーム内の情報が見えてしまう

本ツールでは、課題とその進捗、担当、会話をプロジェクト単位でまとめ、必要なメンバーだけが閲覧・操作できる状態を作ります。

## 4. 想定する利用者

初期リリースでは、2〜10人程度の小規模なチームを想定します。

具体的には、次のような利用者です。

- 個人開発や学習プロジェクトを複数人で進めるチーム
- 小規模な制作・開発案件を管理するチーム
- 大規模な管理機能を必要とせず、簡単に課題を共有したいグループ

## 5. プロダクトの方針

### 5.1 シンプルであること

一覧、詳細、入力フォームを中心とし、初めて使う人でも説明なしで基本操作ができることを目指します。

### 5.2 状況がすぐに分かること

課題の状態、優先度、担当者、期限を一覧で確認できるようにします。必要な課題へすぐたどり着けるよう、絞り込みと検索を提供します。

### 5.3 チームの境界が明確であること

利用者が閲覧・操作できる内容は、参加しているワークスペースと与えられた役割によって決まります。

### 5.4 初期リリースの完成を優先すること

カンバン、リアルタイム共同編集、通知などは初期リリースに含めません。課題管理に必要な基本的な体験を一通り完成させることを優先します。

## 6. 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | 本ツールに登録し、ログインして利用する人 |
| ワークスペース | メンバーとプロジェクトをまとめる、チームの活動領域 |
| メンバー | ワークスペースに参加しているユーザー |
| プロジェクト | 共通の目的を持つ課題をまとめる単位 |
| 課題 | チームが対応・確認すべき作業や問題 |
| コメント | 課題に対して投稿する補足、報告、相談 |
| オーナー | ワークスペース全体を管理する役割 |
| メンバー権限 | プロジェクトと課題の管理に参加する通常の役割 |
| 閲覧者 | 内容の確認だけを行う役割 |

## 7. 情報の構成

本ツールの情報は、次の関係で整理します。

```text
ワークスペース
├── メンバー
└── プロジェクト
    └── 課題
        └── コメント
```

- 一人のユーザーは複数のワークスペースに参加できます。
- 一つのワークスペースは複数のメンバーを持てます。
- 一つのワークスペースは複数のプロジェクトを持てます。
- 一つのプロジェクトは複数の課題を持てます。
- 一つの課題は複数のコメントを持てます。

## 8. 役割と権限

ワークスペースごとに、各ユーザーへ次のいずれかの役割を割り当てます。同じユーザーでも、ワークスペースごとに異なる役割を持つ場合があります。

| 操作 | オーナー | メンバー | 閲覧者 |
| --- | :---: | :---: | :---: |
| ワークスペースを閲覧する | ○ | ○ | ○ |
| ワークスペースの名称を変更する | ○ | － | － |
| メンバーを追加・削除する | ○ | － | － |
| メンバーの役割を変更する | ○ | － | － |
| プロジェクトを作成・編集する | ○ | ○ | － |
| プロジェクトを終了する | ○ | ○ | － |
| 課題を閲覧する | ○ | ○ | ○ |
| 課題を作成・編集する | ○ | ○ | － |
| 課題を削除する | ○ | ○ | － |
| コメントを投稿する | ○ | ○ | － |
| 自分のコメントを編集・削除する | ○ | ○ | － |
| 他人のコメントを削除する | ○ | － | － |

### 8.1 権限に関するルール

- ワークスペースに参加していないユーザーは、そのワークスペース内の情報を閲覧できません。
- 課題の担当者には、同じワークスペースのメンバーだけを指定できます。
- ワークスペースには、常に一人以上のオーナーが必要です。
- 最後のオーナーは、ほかのメンバーをオーナーに変更するまで退出または削除できません。
- オーナー自身がワークスペースを作成した場合、そのユーザーは作成直後からオーナーになります。

## 9. 機能要件

### 9.1 アカウント

ユーザーは、メールアドレス、表示名、パスワードを使ってアカウントを登録できます。

- 登録済みのメールアドレスは重複して使用できません。
- ユーザーはメールアドレスとパスワードでログインできます。
- ログイン状態は、利用者がログアウトするか、一定の条件で無効になるまで維持されます。
- ユーザーは任意のタイミングでログアウトできます。
- ユーザーは自分の表示名を変更できます。
- パスワードを入力する画面では、入力内容を通常は伏せて表示します。
- ログインに失敗した場合、利用者が次に取るべき行動が分かるメッセージを表示します。

パスワード再設定とアカウント削除は、初期リリースには含めません。

### 9.2 ワークスペース

ログインしたユーザーは、新しいワークスペースを作成できます。

- ワークスペースには名称を設定します。
- 作成者は、そのワークスペースのオーナーになります。
- ユーザーは、自分が参加しているワークスペースの一覧を確認できます。
- オーナーはワークスペースの名称を変更できます。
- ワークスペース自体の削除は、初期リリースには含めません。

### 9.3 メンバー管理

オーナーは、登録済みユーザーのメールアドレスを指定して、ワークスペースにメンバーを追加できます。

- 追加時に、オーナー、メンバー、閲覧者のいずれかの役割を設定できます。
- すでに参加しているユーザーを重複して追加することはできません。
- 登録されていないメールアドレスを指定した場合は、追加できない理由を表示します。
- オーナーは、参加中のメンバーの役割を変更できます。
- オーナーは、メンバーをワークスペースから削除できます。
- 削除されたメンバーは、そのワークスペースへアクセスできなくなります。
- メンバーが削除されても、そのメンバーが過去に作成した課題やコメントは残ります。

招待メールの送信や、招待を受けたユーザーによる承認操作は、初期リリースには含めません。

### 9.4 プロジェクト

オーナーとメンバーは、ワークスペース内にプロジェクトを作成できます。

プロジェクトは次の情報を持ちます。

| 項目 | 必須 | 説明 |
| --- | :---: | --- |
| 名称 | ○ | プロジェクトを識別する名称 |
| 説明 | － | 目的や前提を伝える短い説明 |
| 状態 | ○ | 進行中、終了のいずれか |

- 同じワークスペース内で、複数のプロジェクトを作成できます。
- オーナーとメンバーはプロジェクトの名称と説明を変更し、プロジェクトを終了できます。
- 終了したプロジェクトは、新しい課題やコメントを追加できない読み取り専用の状態になります。
- 終了したプロジェクトは一覧から確認でき、オーナーとメンバーは再び進行中に戻せます。
- プロジェクトを完全に削除する機能は、初期リリースには含めません。

### 9.5 課題

オーナーとメンバーは、進行中のプロジェクトに課題を作成できます。

課題は次の情報を持ちます。

| 項目 | 必須 | 説明 |
| --- | :---: | --- |
| タイトル | ○ | 課題の内容を簡潔に表す名称 |
| 説明 | － | 背景、完了条件、補足などを記載する本文 |
| 状態 | ○ | 未着手、対応中、完了のいずれか |
| 優先度 | ○ | 低、中、高のいずれか |
| 担当者 | － | 対応を担当するワークスペースのメンバー |
| 期限 | － | 対応完了の目安となる日付 |
| 作成者 | ○ | 課題を作成したユーザー |
| 作成日時 | ○ | 課題が作成された日時 |
| 更新日時 | ○ | 課題が最後に更新された日時 |

- 課題の作成時は、状態を「未着手」、優先度を「中」とします。作成者は入力時に変更できます。
- オーナーとメンバーは、課題のタイトル、説明、状態、優先度、担当者、期限を変更できます。
- 説明はプレーンテキストを対象とし、装飾や画像の埋め込みは初期リリースに含めません。
- 担当者を設定しない課題も作成できます。
- 担当者がワークスペースから削除された場合、その課題は担当者なしになります。
- オーナーとメンバーは課題を削除できます。削除の前には確認を求めます。
- 削除した課題とそのコメントは、通常の利用画面から確認できなくなります。

### 9.6 課題一覧と検索

ユーザーは、プロジェクト内の課題を一覧で確認できます。

一覧には、少なくとも次の内容を表示します。

- タイトル
- 状態
- 優先度
- 担当者
- 期限
- 更新日時

一覧では次の操作ができます。

- タイトルに含まれる文字で検索する
- 状態で絞り込む
- 優先度で絞り込む
- 担当者で絞り込む
- 担当者が設定されていない課題に絞り込む
- 複数の絞り込み条件を組み合わせる
- 絞り込み条件を解除する
- 更新日時が新しい順または古い順に並べ替える
- 期限が近い順または遠い順に並べ替える

該当する課題がない場合は、データがないのか、検索条件に一致しないのかを区別して案内します。

### 9.7 課題詳細

ユーザーは、課題の詳細画面で登録内容とコメントを確認できます。

- 課題の基本情報とコメントを一つの画面で確認できます。
- 編集権限があるユーザーには、編集操作を表示します。
- 閲覧者には、内容を変更する操作を表示しません。
- 期限を過ぎて完了していない課題は、期限超過であることが分かるように表示します。
- 担当者が設定されていない場合は、そのことが分かる表示にします。

### 9.8 コメント

オーナーとメンバーは、課題にコメントを投稿できます。

- コメントには、本文、投稿者、投稿日時を表示します。
- コメント本文はプレーンテキストとします。
- コメントは古いものから順に表示します。
- 投稿者は自分のコメントを編集・削除できます。
- 編集されたコメントには、編集済みであることを表示します。
- オーナーは、必要に応じてほかのユーザーのコメントを削除できます。
- コメントを削除する前には確認を求めます。

| メンバー管理 | 参加者と役割を管理する | メンバー一覧、追加、役割変更、削除 |
| プロジェクト作成・編集 | 課題をまとめる単位を管理する | 名称、説明、状態 |

## 11. 主な利用シナリオ

### 11.1 チームの活動を開始する

1. ユーザーがアカウントを登録します。
2. ユーザーがワークスペースを作成します。
3. 作成者がオーナーとして参加します。
4. オーナーが登録済みユーザーをメンバーとして追加します。
5. オーナーまたはメンバーがプロジェクトを作成します。

### 11.2 課題を登録して担当する

1. オーナーまたはメンバーがプロジェクトを開きます。
2. タイトル、説明、優先度、担当者、期限を入力して課題を作成します。
3. 担当者が課題を確認し、対応を始めるときに状態を「対応中」へ変更します。
4. 必要に応じてコメントで質問や進捗を共有します。
5. 対応が終わったら状態を「完了」へ変更します。

### 11.3 状況を確認する

1. ユーザーが対象のプロジェクトを開きます。
2. 状態を「未着手」または「対応中」に絞り込みます。
3. 必要に応じて担当者や優先度を追加で指定します。
4. 課題の詳細を開き、説明とコメントを確認します。

### 11.4 閲覧者として参加する

1. オーナーがユーザーを閲覧者としてワークスペースに追加します。
2. 閲覧者がプロジェクトと課題を確認します。
3. 閲覧者には作成、編集、削除、コメント投稿の操作は表示されません。

## 12. 表示と操作の共通方針

- 入力に誤りがある場合は、該当する項目の近くに理由を表示します。
- 保存、削除などの処理が失敗した場合は、失敗したことと再試行できることを明確に伝えます。
- 削除や終了など、元に戻しにくい操作では事前に確認を求めます。
- 操作する権限がない場合は、実行できない操作を原則として表示しません。
- 一覧が空の場合は、次にできる行動を案内します。
- 日時は利用者が理解しやすい一貫した形式で表示します。
- スマートフォンでも閲覧と主要な操作ができることを目指します。

## 13. 初期リリースに含めない機能

次の機能は、初期リリースの完成後に必要性を判断します。

- カンバン形式の表示とドラッグ＆ドロップ
- 課題の自由な並べ替え
- リアルタイムの共同編集や自動更新
- メール、アプリ内、外部サービスへの通知
- 招待メールと招待の承認
- パスワード再設定
- アカウント削除
- ワークスペースの削除
- ファイルや画像の添付
- 装飾付きの本文やMarkdown記法
- タグ、子課題、チェックリスト
- 課題の一括編集
- 作業時間の記録
- カレンダー表示
- グラフや分析ダッシュボード
- 外部サービスとの連携
- 多言語対応

## 14. 初期リリースの完成条件

以下をすべて満たした時点で、初期リリースが完成したものとします。

- ユーザーが登録、ログイン、ログアウトできる
- ユーザーがワークスペースを作成できる
- オーナーが登録済みユーザーを追加し、役割を管理できる
- オーナーとメンバーがプロジェクトを作成・編集・終了できる
- オーナーとメンバーが課題を作成・編集できる
- オーナーとメンバーが課題を削除できる
- ユーザーが課題を検索、絞り込み、並べ替えできる
- オーナーとメンバーがコメントを投稿できる
- 閲覧者が変更操作を行えない
- ワークスペース外のユーザーが情報を閲覧できない
- 入力エラー、権限不足、対象が存在しない場合に、利用者が状況を理解できる
- パソコンとスマートフォンの双方で主要な操作を完了できる

## 15. 将来の検討候補

初期リリース後は、実際に使って不便を感じた箇所から改善します。候補として、次の機能を想定します。

- 招待制のメンバー追加
- 変更履歴と活動履歴
- タグやマイルストーン
- 課題の親子関係
- 通知と期限のリマインド
- ファイル添付
- カンバン表示
- ダッシュボード
- 完了した課題の再利用やテンプレート

追加機能は、初期リリースの使いやすさと保守性を損なわない範囲で検討します。
