# IssueDock プロダクトバックログ

## 1. この文書について

この文書は、IssueDockの初期リリースに必要な作業を、機能および利用者の行動単位で整理したものです。チーム全体が、次に作るもの、作る理由、完了と判断する条件を共有するために使用します。

作るものの詳細は[プロダクト仕様書](./product-specification.md)を基準とします。この文書では、使用する技術、システム構成、データの保存方法、外部との通信方法などの技術設計は扱いません。

| 項目 | 内容 |
| --- | --- |
| 文書の状態 | 初版 |
| 対象 | 初期リリース（MVP） |
| 最終更新日 | 2026-09-17 |
| 関連文書 | [IssueDock プロダクト仕様書](./product-specification.md) |

## 2. 進め方

### 2.1 作業順

マイルストーンは、利用者が一連の操作を試せる範囲を少しずつ広げる順番で並べています。原則として番号順に進めます。

| 順序 | マイルストーン | 到達する状態 |
| --- | --- | --- |
| 1 | 利用を開始できる | ユーザーが登録し、継続して利用できる |
| 2 | 活動場所を作れる | 自分のワークスペースを作成・選択できる |
| 3 | チームを作れる | メンバーと役割を管理できる |
| 4 | 仕事を分類できる | プロジェクトを作成・管理できる |
| 5 | 課題を管理できる | 課題の登録から完了までを管理できる |
| 6 | 必要な課題を探せる | 検索、絞り込み、並べ替えができる |
| 7 | 課題について会話できる | コメントで補足や相談ができる |
| 8 | 安心して共同利用できる | 役割と所属範囲に応じて操作が制限される |
| 9 | 初期リリースを提供できる | 主要な利用の流れを問題なく完了できる |

### 2.2 状態の管理

各作業項目のチェックボックスを使って進捗を管理します。

- `[ ]`：未着手
- 項目名の末尾に「（進行中）」を付ける：進行中
- 項目名の末尾に「（確認待ち）」を付ける：確認待ち
- `[x]`：完了
- 保留する場合は、項目の直下に理由と再開条件を記載する

### 2.3 優先順位

この文書に掲載する作業は、すべて初期リリースに必要です。上から順番に進め、同じマイルストーン内では依存関係の少ない項目を優先します。

新しい要望が出た場合は、すぐに作業へ追加せず、プロダクト仕様書の初期リリース範囲に含めるかを先に判断します。

## 3. 共通の完了条件

個別の完了条件に加え、すべての作業項目で次の条件を満たすものとします。

- 利用者が目的の操作を最初から最後まで完了できる
- 入力に誤りがある場合、理由と修正方法が分かる
- 操作に失敗した場合、失敗したことと次に取れる行動が分かる
- 操作権限がある利用者とない利用者で、仕様どおりの振る舞いになる
- 情報がない状態でも、現在の状況と次にできる行動が分かる
- パソコンとスマートフォンの両方で主要な操作を完了できる
- 実際の振る舞いとプロダクト仕様書の内容が一致している

## 4. 作業リスト

### マイルストーン1：利用を開始できる

このマイルストーンでは、ユーザーがIssueDockの利用を開始し、後から同じアカウントで利用を再開できる状態を目指します。

- [ ] **ACC-01 アカウントを登録する**
  - 利用者は、メールアドレス、表示名、パスワードを入力して利用を開始できる。
  - 登録済みのメールアドレスは重複して使用できない。
  - 入力に問題がある場合、修正が必要な項目を確認できる。

- [ ] **ACC-02 ログインする**
  - 登録済みの利用者は、メールアドレスとパスワードでログインできる。
  - 誤った情報でログインできず、利用者には再確認を促す案内が表示される。
  - ログイン後、IssueDockの利用を継続できる。

- [ ] **ACC-03 ログアウトする**
  - ログイン中の利用者は、任意のタイミングでログアウトできる。
  - ログアウト後は、ログインが必要な情報を閲覧・操作できない。

- [ ] **ACC-04 自分の情報を確認・変更する**
  - 利用者は、自分の表示名とメールアドレスを確認できる。
  - 利用者は、自分の表示名を変更できる。
  - 変更後の表示名が、IssueDock内の自分を表す名前として使用される。

### マイルストーン2：活動場所を作れる

このマイルストーンでは、ユーザーがチームの活動場所となるワークスペースを作成し、参加先を選べる状態を目指します。

- [ ] **WSP-01 ワークスペースを作成する**
  - ログイン中の利用者は、名称を入力してワークスペースを作成できる。
  - 作成した利用者は、そのワークスペースのオーナーになる。
  - 作成後、利用者はそのワークスペースで活動を始められる。

- [ ] **WSP-02 参加中のワークスペースを確認・選択する**
  - 利用者は、自分が参加しているワークスペースの一覧を確認できる。
  - 複数のワークスペースに参加している場合、利用するワークスペースを選択できる。
  - 参加しているワークスペースがない場合、作成を促す案内を確認できる。

- [ ] **WSP-03 ワークスペースの名称を変更する**
  - オーナーは、ワークスペースの名称を変更できる。
  - 変更された名称は、そのワークスペースに参加している全員に表示される。
  - メンバーと閲覧者は名称を変更できない。

### マイルストーン3：チームを作れる

このマイルストーンでは、オーナーが登録済みユーザーをワークスペースに追加し、役割を管理できる状態を目指します。

- [ ] **MEM-01 ワークスペースの参加者を確認する**
  - ワークスペースの参加者は、参加中のユーザーとそれぞれの役割を確認できる。
  - 各ユーザーの表示名と役割を区別できる。

- [ ] **MEM-02 登録済みユーザーを追加する**
  - オーナーは、登録済みのメールアドレスを指定してユーザーを追加できる。
  - 追加時に、オーナー、メンバー、閲覧者のいずれかの役割を指定できる。
  - 未登録のユーザーや参加済みのユーザーを追加しようとした場合、追加できない理由を確認できる。
  - オーナー以外の利用者はユーザーを追加できない。

- [ ] **MEM-03 参加者の役割を変更する**
  - オーナーは、参加者の役割を変更できる。
  - 変更後は、新しい役割に応じた操作だけを行える。
  - 最後のオーナーを別の役割へ変更することはできない。

- [ ] **MEM-04 参加者を削除する**
  - オーナーは、参加者をワークスペースから削除できる。
  - 削除対象と影響を確認してから操作を確定できる。
  - 削除されたユーザーは、そのワークスペースへアクセスできない。
  - 削除されたユーザーが過去に作成した課題やコメントは残る。
  - 最後のオーナーを削除することはできない。

### マイルストーン4：仕事を分類できる

このマイルストーンでは、オーナーとメンバーがプロジェクトを作り、課題を目的ごとに整理できる状態を目指します。

- [ ] **PRJ-01 プロジェクトを作成する**
  - オーナーとメンバーは、名称と説明を入力してプロジェクトを作成できる。
  - 作成したプロジェクトは「進行中」として利用を開始できる。
  - 閲覧者はプロジェクトを作成できない。

- [ ] **PRJ-02 プロジェクトを確認する**
  - ワークスペースの参加者は、プロジェクトの一覧を確認できる。
  - 各プロジェクトの名称、説明、状態を確認できる。
  - 進行中と終了済みのプロジェクトを区別できる。

- [ ] **PRJ-03 プロジェクトを編集する**
  - オーナーとメンバーは、プロジェクトの名称と説明を変更できる。
  - 変更内容は、ワークスペースの参加者全員に表示される。
  - 閲覧者はプロジェクトを編集できない。

- [ ] **PRJ-04 プロジェクトを終了・再開する**
  - オーナーとメンバーは、進行中のプロジェクトを終了できる。
  - 終了前に、操作による影響を確認できる。
  - 終了したプロジェクトは閲覧できるが、課題やコメントを追加・変更できない。
  - オーナーとメンバーは、終了したプロジェクトを再開できる。

### マイルストーン5：課題を管理できる

このマイルストーンでは、オーナーとメンバーが課題を登録し、担当や進捗を更新して完了まで管理できる状態を目指します。

- [ ] **ISS-01 課題を作成する**
  - オーナーとメンバーは、進行中のプロジェクトに課題を作成できる。
  - タイトルを必須とし、説明、状態、優先度、担当者、期限を設定できる。
  - 初期状態は「未着手」、初期優先度は「中」となり、作成時に変更できる。
  - 閲覧者は課題を作成できない。

- [ ] **ISS-02 課題の一覧を確認する**
  - ワークスペースの参加者は、課題の一覧を確認できる。
  - 一覧でタイトル、状態、優先度、担当者、期限、更新日時を確認できる。
  - 課題がない場合、最初の課題を作成するための案内を確認できる。

- [ ] **ISS-03 課題の詳細を確認する**
  - ワークスペースの参加者は、課題に登録されたすべての情報を確認できる。
  - 担当者がいない場合、そのことを確認できる。
  - 完了していない課題が期限を過ぎている場合、期限超過であることを確認できる。

- [ ] **ISS-04 課題の内容を編集する**
  - オーナーとメンバーは、タイトル、説明、状態、優先度、担当者、期限を変更できる。
  - 担当者には、同じワークスペースに参加しているユーザーだけを指定できる。
  - 担当者を設定しない状態へ戻すことができる。
  - 閲覧者は課題を編集できない。

- [ ] **ISS-05 課題の進捗を更新する**
  - オーナーとメンバーは、課題を「未着手」「対応中」「完了」の間で変更できる。
  - 変更後の状態が一覧と詳細の両方に反映される。
  - 完了した課題も引き続き確認できる。

- [ ] **ISS-06 課題を削除する**
  - オーナーとメンバーは課題を削除できる。
  - 削除対象と影響を確認してから操作を確定できる。
  - 削除した課題とそのコメントは、通常の利用画面から確認できない。
  - 閲覧者は課題を削除できない。

### マイルストーン6：必要な課題を探せる

このマイルストーンでは、課題が増えても、利用者が対応すべき課題へすぐにたどり着ける状態を目指します。

- [ ] **FND-01 タイトルで課題を検索する**
  - 利用者は、タイトルに含まれる文字を使って課題を検索できる。
  - 検索条件を解除し、すべての課題を再表示できる。
  - 一致する課題がない場合、そのことを確認できる。

- [ ] **FND-02 条件で課題を絞り込む**
  - 利用者は、状態、優先度、担当者で課題を絞り込める。
  - 担当者が設定されていない課題だけを表示できる。
  - 複数の条件を組み合わせられる。
  - すべての条件を解除できる。

- [ ] **FND-03 課題を並べ替える**
  - 利用者は、更新日時の新しい順と古い順を選択できる。
  - 利用者は、期限の近い順と遠い順を選択できる。
  - 並べ替えの基準と順番を確認できる。

- [ ] **FND-04 検索結果がない理由を理解する**
  - プロジェクトに課題自体がない場合と、条件に一致する課題がない場合を区別できる。
  - 条件に一致しない場合、検索や絞り込みを解除する操作へ進める。

### マイルストーン7：課題について会話できる

このマイルストーンでは、課題に関する補足、相談、進捗報告を一か所に残せる状態を目指します。

- [ ] **CMT-01 コメントを確認・投稿する**
  - ワークスペースの参加者は、コメントを古いものから順に確認できる。
  - 各コメントの本文、投稿者、投稿日時を確認できる。
  - オーナーとメンバーはコメントを投稿できる。
  - 閲覧者はコメントを閲覧できるが、投稿できない。

- [ ] **CMT-02 自分のコメントを編集する**
  - オーナーとメンバーは、自分が投稿したコメントを編集できる。
  - 編集したコメントには、編集済みであることが表示される。
  - 他人のコメントは編集できない。

- [ ] **CMT-03 自分のコメントを削除する**
  - オーナーとメンバーは、自分が投稿したコメントを削除できる。
  - 削除対象を確認してから操作を確定できる。
  - 削除したコメントは課題の詳細から確認できない。

- [ ] **CMT-04 不適切なコメントを管理する**
  - オーナーは、ほかのユーザーが投稿したコメントを削除できる。
  - メンバーと閲覧者は、ほかのユーザーのコメントを削除できない。
  - 削除対象を確認してから操作を確定できる。

### マイルストーン8：安心して共同利用できる

このマイルストーンでは、ワークスペースへの所属と役割に応じて、閲覧・操作できる範囲が一貫して守られる状態を目指します。

- [ ] **AUT-01 ワークスペース外の情報を保護する**
  - 利用者は、自分が参加していないワークスペースを一覧で確認できない。
  - 参加していないワークスペース、そのプロジェクト、課題、コメントを閲覧・操作できない。
  - アクセスできない場合、利用者が状況を理解できる案内が表示される。

- [ ] **AUT-02 オーナーの管理権限を確認する**
  - オーナーは、ワークスペースの名称、参加者、役割を管理できる。
  - オーナーは、プロジェクト、課題、コメントについて仕様で定めた操作を行える。
  - ワークスペースには常に一人以上のオーナーが残る。

- [ ] **AUT-03 メンバーの操作範囲を確認する**
  - メンバーは、プロジェクトを作成・編集・終了できる。
  - メンバーは、課題を作成・編集・削除できる。
  - メンバーはコメントを投稿し、自分のコメントを編集・削除できる。
  - メンバーは、ワークスペースの名称、参加者、役割を管理できない。
  - メンバーは、ほかのユーザーのコメントを削除できない。

- [ ] **AUT-04 閲覧者の操作範囲を確認する**
  - 閲覧者は、参加中のワークスペース、プロジェクト、課題、コメントを閲覧できる。
  - 閲覧者には、作成、編集、削除、投稿などの変更操作が表示されない。
  - 閲覧者は、直接変更を試みても操作を完了できない。

- [ ] **AUT-05 終了したプロジェクトの制限を確認する**
  - 終了したプロジェクトと、その課題やコメントは引き続き閲覧できる。
  - 終了中は、課題とコメントを追加・変更・削除できない。
  - プロジェクトを再開すると、役割に応じて変更操作を再び行える。

### マイルストーン9：初期リリースを提供できる

このマイルストーンでは、個別機能だけでなく、利用者の目的を最初から最後まで達成できることを確認します。

- [ ] **REL-01 チームの活動開始を通して確認する**
  - 新規ユーザーが登録してワークスペースを作成できる。
  - オーナーが別の登録済みユーザーを追加できる。
  - オーナーまたはメンバーがプロジェクトを作成できる。
  - 途中で迷ったり、操作を続けられなくなったりする箇所がない。

- [ ] **REL-02 課題の完了までを通して確認する**
  - オーナーまたはメンバーが課題を登録し、担当者と期限を設定できる。
  - 担当者が進捗を「対応中」から「完了」へ更新できる。
  - 関係者がコメントで補足や進捗を共有できる。
  - 完了後も、課題とコメントを振り返ることができる。

- [ ] **REL-03 複数の役割で利用を確認する**
  - オーナー、メンバー、閲覧者の各利用者が、許可された操作を完了できる。
  - 各利用者が、許可されていない情報の閲覧や操作を行えない。
  - 役割を変更した場合、新しい役割に応じた利用状態になる。

- [ ] **REL-04 課題を探す流れを通して確認する**
  - 課題が複数ある状態で、検索、絞り込み、並べ替えを組み合わせられる。
  - 担当中の課題や期限の近い課題へ迷わずたどり着ける。
  - 条件に一致する課題がない場合、条件を変更して作業を続けられる。

- [ ] **REL-05 パソコンとスマートフォンで利用を確認する**
  - アカウント登録、ログイン、ワークスペース選択を完了できる。
  - プロジェクトと課題の閲覧、作成、編集を完了できる。
  - コメントの閲覧と投稿を完了できる。
  - 主要な情報や操作が画面から欠けない。

- [ ] **REL-06 初期リリースの最終確認を行う**
  - プロダクト仕様書の完成条件をすべて満たしている。
  - このバックログの初期リリース項目がすべて完了している。
  - 既知の問題がある場合、内容、影響、対応方針がチームで共有されている。
  - 初期リリースに含めない機能が、誤って追加されていない。

## 5. 初期リリース後に検討する項目

次の項目は、初期リリースの作業には含めません。初期リリースを実際に使った結果を基に、必要性と優先順位を改めて判断します。

- 招待制のメンバー追加
- パスワード再設定とアカウント削除
- ワークスペースの削除
- 通知と期限のリマインド
- ファイルや画像の添付
- タグ、子課題、チェックリスト
- 課題の一括編集と自由な並べ替え
- 変更履歴と活動履歴
- カンバン、カレンダー、ダッシュボード
- リアルタイムの共同編集や自動更新
- 外部サービスとの連携
- 多言語対応

これらの項目に着手する場合は、先にプロダクト仕様書の対象範囲を更新します。
